# AI_NOTES.md

## Инструменты
Работал с Claude (Opus) в режиме диалога (backend) и автономный агент (frontend), а пошаговое обсуждение архитектуры с последующей генерацией кода на каждом этапе.

## Что делегировал AI
- Генерацию кода нескольких слоёв backend на основе согласованных архитектурных решений.
- Написание EF Core конфигураций и разбор нетривиального маппинга value object (Money) —
  сходу не знал про ComplexProperty (замена OwnsOne для struct), AI подсказал и объяснил разницу.
- Генератор seed-данных целиком (распределения, сезонность, "сила" менеджеров) — эту часть
  сознательно отдал AI почти полностью, так как объём кода большой, а логика механическая.
- Frontend делегировал AI-агенту почти полностью (структура FSD, компоненты, стили,
  запросы к API, анимации) — по сгенерированному детальному промпту с полными
  контрактами API и требованиями к UI/UX. Из-за ограниченности timebox не было
  возможности вычитывать и переписывать frontend-код так же тщательно, построчно,
  как backend — проверял на уровне работающего результата

## Что проектировал самостоятельно
- Общую архитектуру (Clean Architecture + элементы DDD, слои Domain/Application/Infrastructure/Host).
- Решение по трактовке Refunded-статуса и правилам сравнения периодов — обсуждал с AI
  варианты, но финальное решение принимал сам.
- Выбор между IQueryable-репозиториями и специализированными методами (Вариант Б) —
  попросил сравнение, оценил компромиссы, выбрал сам исходя из тестируемости.
- Все точечные решения по упрощению (убрал избыточные DDD-абстракции Entity<TId>/
  AggregateRoot<TId>/ValueObject, убрал CategoryName из ProductBreakdownDto).

## Где AI заметно ускорил работу
- Полная генерация boilerplate-кода репозиториев/DTO/конфигураций — то, что заняло бы
  час-полтора рутинного набора текста, ушло на review за 10-15 минут.
- Быстрая диагностика непонятных runtime-исключений (Npgsql, EF CLI)

## Где AI ошибся / что пришлось поправить
- Первая версия Domain-слоя была избыточно "академичной" (полноценные DDD-базовые классы
  Entity<TId>, AggregateRoot<TId>, ValueObject) — для масштаба этого проекта это оверинжиниринг, явно попросил упростить.
- В Sale.Cancel() не было проверки на повторную отмену (только на Refunded) — заметил
  асимметрию с Refund() и попросил исправить.
- В формуле группировки по неделям (тренд-график) AI перепутал ветки тернарного оператора
  при добавлении правки "неделя с понедельника" — поймал на review, попросил переисправить.
- Метод GetAllWithCategoryAsync остался как NotImplementedException-заглушка после того как
  we решили убрать поле категории из DTO — не полностью подчистил все три места (интерфейс,
  реализация, вызов), пришлось указать на это явно после ошибки в рантайме.

## Как проверял итоговый код
- Каждый крупный кусок (Domain, Application-контракты, Infrastructure) проверял через
  прямые вопросы "зачем это нужно".
- Реальный прогон приложения на каждом этапе (сборка, миграции, seed, ручные запросы через
  Scalar) — не принимал код "на веру", ловил реальные runtime-ошибки и разбирал их с AI.
- Читал сгенерированный SQL/миграции глазами перед тем как двигаться дальше.
